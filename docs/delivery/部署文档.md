### 1.3 术语

“API”指 Spring Boot 后端服务；“Flyway”指按版本顺序执行数据库迁移的组件；“SSE（Server-Sent Events）”指浏览器通过 HTTP 长连接接收服务端事件；“虚拟执行”指在软件仿真器中生成 ACK 和效果数据，不代表真实水泵或阀门已动作。

### 1.4 交付内容

发布包包含可执行 JAR、Vite 静态文件、Flyway 迁移、虚拟演示种子、配置模板和运维脚本。发布包不含 Java/前端/微信小程序源代码、依赖缓存、数据库备份、日志、运行期附件、`.env` 或模型权重；源码、数据库文件和两份正式文档在项目交付总包中分别提供。演示账号仅用于首次登录和功能演示，部署后必须修改密码和密钥。

## 二、系统组成与部署拓扑

### 2.1 组成

| 组件 | 作用 | 发布包形态 | 默认监听 |
|---|---|---|---|
| Web 静态资源 | Vue/Vite 页面、ECharts 图表和登录页 | `web/` | 由 Nginx 提供 |
| API 服务 | 认证、业务规则、模拟器、REST、SSE | `api/api-service-0.1.0.jar` | `127.0.0.1:8080` |
| PostgreSQL | 业务记录、遥测、事件和账号持久化 | 主机软件 | `127.0.0.1:5432` |
| Redis | Redis Streams 遥测事件通道和健康状态 | 主机软件 | `127.0.0.1:6379` |
| Mosquitto | MQTT 设备/命令桥接 | 主机软件 | `127.0.0.1:1883` |
| Supervisor | API 进程守护和自动重启 | 主机软件 | 本机 UNIX socket |
| Nginx | 静态文件、反向代理和公网入口 | 主机软件 | `:80` |
| 可选 vLLM | OpenAI 兼容本地模型服务 | 另行安装 | `127.0.0.1:8000` |

### 2.2 拓扑

~~~text
浏览器
  │ HTTP/HTTPS :80（外部反向代理可映射为 :8443）
  ▼
Nginx ── /agriloop/、/farm-admin/、/farmer/、/system-admin/
  │
  ├── 静态文件：/srv/agriloop/current/web
  └── /api/、/actuator/、/v3/ ──► API 127.0.0.1:8080
                                      │
                    ┌─────────────────┼────────────────┐
                    ▼                 ▼                ▼
              PostgreSQL          Redis Streams       Mosquitto
              127.0.0.1:5432      127.0.0.1:6379      127.0.0.1:1883
                                      │                │
                                      └── BearPi 桥接（可选）
~~~

浏览器不直接连接 MQTT，也不接触 Redis、数据库或模型服务凭据。模拟器运行在 API 进程内的 `SimulationEngine`，不会绕过 API 直接写入告警、Agent 结论或最终控制结果。

## 三、硬件配置要求

### 3.1 服务器最低配置

| 资源 | 最低要求 | 推荐配置 | 说明 |
|---|---:|---:|---|
| CPU | 4 vCPU | 8 vCPU | API、数据库、消息代理和 Nginx 同机部署时使用推荐值 |
| 内存 | 8 GB | 16 GB | 不含本地大模型；模拟器采样和历史数据增大时应增加 |
| 磁盘 | 20 GB 可用 | 50 GB 以上 | 包含系统、JAR、日志、数据库和备份；模型权重不计入发布包 |
| 网络 | 1 Mbps、可访问软件源 | 10 Mbps 以上 | 安装阶段需要访问 Ubuntu 软件源；公网入口需可被验收机访问 |
| GPU | 规则模式不要求 | 使用本地模型时推荐总显存不低于 90 GB | 使用 Qwen3.8-27B + vLLM 时，推荐 GPU 总显存不低于 90 GB；模型服务不随交付物提供 |

### 3.2 可选硬件

支持的真实硬件链路为 BearPi HM Nano 搭配 E53_IA1 扩展板：板端遥测经串口桥接到 MQTT，再由 API 转为 REST/SSE 事件；板载风扇和补光灯的受控链路包含 `AT+AGRI` 命令和固件 ACK。真实水泵、阀门、其他 GPIO 执行器和未适配传感器需要另行开发和现场验证。

硬件桥接需要额外的 Python 3.10+ 环境、串口设备权限和 MQTT 网络可达性，具体固件和接线说明见源码包 `docs/hardware/bearpi-e53-ia1.md`。没有开发板时使用软件仿真不影响本部署验收。

~~~bash
  --tensor-parallel-size 2 \
~~~



页面会显示规则模式/降级状态，不会把规则结果伪装成模型结果。使用规则模式时无需下载模型权重；使用本地模型时应准备总显存不低于 90 GB 的 GPU，并为模型权重预留足够磁盘空间。

### 4.3 三平台支持矩阵

| 平台 | 完整部署方式 | 可直接使用的材料 | 说明 |
|---|---|---|---|
| Linux（Ubuntu Server 22.04 x86_64） | 原生发布包（推荐）或 Docker Compose | `agriloop-release-linux-x86_64.zip`、源码包中的 `infra/` | 原生方式提供 API、PostgreSQL、Redis、Mosquitto、Supervisor、Nginx；Docker 方式提供同等应用拓扑 |
| Windows 10/11 x86_64 | Docker Desktop + Linux containers | 源码包中的 `infra/docker-compose.yml` | Docker Compose 完整启动数据库、Redis、Mosquitto、API、演示种子和 Web；不要求在 Windows 安装 JDK/Node.js |
| macOS 12 或更高（Intel/Apple Silicon） | Docker Desktop + Linux containers | 源码包中的 `infra/docker-compose.yml` | Docker Desktop 提供完整应用拓扑；Apple Silicon 使用 Docker 的 arm64 镜像，构建失败时切换 amd64 仿真 |

JAR 本身是 Java 跨平台产物。Linux 发布 ZIP 的安装脚本依赖 Ubuntu 服务管理工具；Windows 和 macOS 使用 Docker Desktop 执行 Compose 文件，以获得与 Linux 相同的 PostgreSQL、Redis、Mosquitto、API 和 Web 运行拓扑。

### 4.4 Windows 本地运行

Windows 使用 Docker Desktop 的 Linux containers 模式部署完整应用。以下步骤同时启动 PostgreSQL、Redis、Mosquitto、API、演示种子和 Nginx Web，不要求在 Windows 主机安装 JDK、Node.js 或数据库。

#### 4.4.1 安装前置软件

1. 安装 Windows 10 22H2 或 Windows 11，并在 BIOS/UEFI 中启用 CPU 虚拟化。
2. 以管理员身份打开 PowerShell，安装 WSL2：

~~~powershell
wsl --install
~~~

3. 重启 Windows，安装 [Docker Desktop](https://www.docker.com/products/docker-desktop/)，在设置中启用“Use the WSL 2 based engine”，并确认使用 Linux containers。
4. 在普通 PowerShell 中验证运行环境：

~~~powershell
wsl --status
docker version
docker compose version
~~~

预期结果是客户端和服务端均可连接，`docker compose version` 返回 Compose V2 版本。若提示无法连接 Docker daemon，启动 Docker Desktop 并等待状态显示为 Running。

#### 4.4.2 解压源码交付包

以下示例假设 `agriloop-source.zip` 位于下载目录。目标目录不得包含旧版 `.env`、数据库目录或 Docker volume：

~~~powershell
New-Item -ItemType Directory -Force C:\agriloop | Out-Null
Expand-Archive -LiteralPath "$env:USERPROFILE\Downloads\agriloop-source.zip" -DestinationPath C:\agriloop
Set-Location C:\agriloop\agriloop-source
Test-Path .\infra\docker-compose.yml
~~~

最后一条命令应返回 `True`。也可使用仓库地址获取同一源码：

~~~powershell
git clone https://github.com/FlowerNeverFade/smart-agriculture.git C:\agriloop\smart-agriculture
Set-Location C:\agriloop\smart-agriculture
~~~

两种获取方式任选其一，后续命令均在所选源码根目录执行。

#### 4.4.3 生成受保护配置

以下 PowerShell 命令生成数据库密码和 JWT 签名密钥，并写入 Git 已忽略的 `.env`。不要把生成结果写入文档、截图或代码仓库：

~~~powershell
$rng = [System.Security.Cryptography.RandomNumberGenerator]::Create()
function New-RandomHex([int]$ByteCount) {
  $buffer = New-Object byte[] $ByteCount
  $rng.GetBytes($buffer)
  return -join ($buffer | ForEach-Object { $_.ToString('x2') })
}
$databasePassword = New-RandomHex 24
$jwtSecret = New-RandomHex 32
@"
POSTGRES_DB=agri
POSTGRES_USER=agri
POSTGRES_PASSWORD=$databasePassword
JWT_SECRET=$jwtSecret
AI_MODE=rules-only
POSTGRES_PORT=5432
REDIS_PORT=6379
MQTT_PORT=1883
API_PORT=8080
WEB_PORT=3000
"@ | Set-Content -LiteralPath .env -Encoding ascii
$rng.Dispose()
~~~

验证 Compose 配置，不输出密码值：

~~~powershell
docker compose --env-file .env -f infra\docker-compose.yml config --quiet
~~~

命令无输出且退出码为 0 表示语法和必要变量有效。`.env` 必须保留在本机，不得加入源码 ZIP。

#### 4.4.4 构建并启动全部服务

~~~powershell
docker compose --env-file .env -f infra\docker-compose.yml up -d --build
docker compose --env-file .env -f infra\docker-compose.yml ps -a
~~~

首次构建需要下载基础镜像和 Maven/Gradle、npm 依赖，完成时间取决于网络。`postgres`、`redis`、`mqtt`、`api`、`web` 应显示 `Up` 或 `healthy`；`seed` 应显示 `Exited (0)`。`seed` 是可重复执行的初始化任务，退出码 0 表示演示数据导入成功。

#### 4.4.5 验证数据库、API 和页面

1. 验证五个 Flyway 迁移：

~~~powershell
docker compose --env-file .env -f infra\docker-compose.yml exec -T postgres `
  psql -U agri -d agri -c "SELECT version,description,success FROM flyway_schema_history ORDER BY installed_rank;"
~~~

2. 验证演示账号：

~~~powershell
docker compose --env-file .env -f infra\docker-compose.yml exec -T postgres `
  psql -U agri -d agri -c "SELECT username,role_code,enabled FROM user_account ORDER BY username;"
~~~

预期包含 `V1` 至 `V5` 五条成功迁移，以及 `farmer`、`admin`、`sysadmin` 三个启用账号。

3. 验证 Nginx 代理后的健康接口：

~~~powershell
$health = Invoke-RestMethod http://127.0.0.1:3000/actuator/health
$health.status
~~~

预期输出 `UP`。

4. 验证农场管理员登录，不输出访问令牌：

~~~powershell
$body = @{ username='admin'; password='demo123'; role='FARM_ADMIN' } | ConvertTo-Json
$login = Invoke-RestMethod -Method Post -Uri http://127.0.0.1:3000/api/v1/auth/login `
  -ContentType 'application/json' -Body $body
$login.data.user.role
~~~

预期输出 `FARM_ADMIN`。浏览器入口为：

~~~text
http://127.0.0.1:3000/agriloop/
http://127.0.0.1:3000/farm-admin/
http://127.0.0.1:3000/farmer/
http://127.0.0.1:3000/system-admin/
~~~

#### 4.4.6 日志、停止和重新启动

~~~powershell
docker compose --env-file .env -f infra\docker-compose.yml logs --tail 100 api web
docker compose --env-file .env -f infra\docker-compose.yml stop
docker compose --env-file .env -f infra\docker-compose.yml start
docker compose --env-file .env -f infra\docker-compose.yml ps -a
~~~

`stop` 不删除 PostgreSQL 和 Redis volume。仅在确认不再需要任何本地业务数据时才可执行 `docker compose ... down -v`；该命令会删除数据库 volume，不用于正常停止。

### 4.5 macOS 本地运行

macOS 使用 Docker Desktop 部署完整应用。Intel 与 Apple Silicon 均执行同一组 Compose 命令，不要求在 macOS 主机安装 JDK、Node.js 或数据库。

#### 4.5.1 安装前置软件

1. 安装 macOS 12 或更高版本。
2. 从 [Docker Desktop for Mac](https://www.docker.com/products/docker-desktop/) 下载与处理器架构匹配的版本并启动。
3. 打开终端验证：

~~~bash
docker version
docker compose version
uname -m
~~~

`uname -m` 在 Intel 主机返回 `x86_64`，在 Apple Silicon 返回 `arm64`。Docker 客户端和服务端均应正常返回版本。

#### 4.5.2 解压源码交付包

~~~bash
mkdir -p "$HOME/agriloop"
unzip "$HOME/Downloads/agriloop-source.zip" -d "$HOME/agriloop"
cd "$HOME/agriloop/agriloop-source"
test -f infra/docker-compose.yml
~~~

最后一条命令退出码应为 0。也可使用仓库地址获取同一源码：

~~~bash
git clone https://github.com/FlowerNeverFade/smart-agriculture.git "$HOME/agriloop/smart-agriculture"
cd "$HOME/agriloop/smart-agriculture"
~~~

两种获取方式任选其一，后续命令均在所选源码根目录执行。

#### 4.5.3 生成受保护配置

~~~bash
database_password="$(openssl rand -hex 24)"
jwt_secret="$(openssl rand -hex 32)"
cat > .env <<EOF
POSTGRES_DB=agri
POSTGRES_USER=agri
POSTGRES_PASSWORD=$database_password
JWT_SECRET=$jwt_secret
AI_MODE=rules-only
POSTGRES_PORT=5432
REDIS_PORT=6379
MQTT_PORT=1883
API_PORT=8080
WEB_PORT=3000
EOF
chmod 600 .env
unset database_password jwt_secret
docker compose --env-file .env -f infra/docker-compose.yml config --quiet
~~~

最后一条命令无输出且退出码为 0 表示配置有效。`.env` 只保存在本机，不得提交到 Git。

#### 4.5.4 构建并启动全部服务

~~~bash
docker compose --env-file .env -f infra/docker-compose.yml up -d --build
~~~

## 六、数据库初始化

### 6.1 操作目的

创建空的 PostgreSQL 数据库和应用账号，由 API 启动时的 Flyway 自动执行五个迁移，再按需导入虚拟演示数据。

### 6.2 前置条件

已完成第五章检查；PostgreSQL 可以由安装脚本安装并启动；`config/env.example` 中的 `DATABASE_NAME`、`DATABASE_USER`、`DATABASE_PASSWORD` 将由部署人员确认。

### 6.3 迁移文件

迁移必须按以下顺序执行，不能重排或跳过：

~~~text
V1__agriloop_core.sql
V2__account_management.sql
V3__social_identity.sql
V4__three_role_scopes.sql
V5__telemetry_source_provenance.sql
~~~

运行时来源是 JAR 内的 `db/migration`；交付目录 `02-数据库文件/migrations/` 和发布包 `db/migrations/` 是经过哈希校验的副本。

### 6.4 演示环境配置

独立安装检查使用以下设置：

~~~dotenv
SEED_DATA=false
DEMO_SEED=true
~~~

`SEED_DATA=false` 防止 API 内置启动种子写入动态数据；安装脚本在 API 健康后执行 `db/demo-seed.sql`。种子只包含虚拟 ID `farm-demo`、`plot-a01`、`plot-a02`、`plot-b01`、`mock-*`、`batch-*`、`resource-default` 和 `case-seed-001` 至 `case-seed-003`，没有遥测历史或生产记录。

正式生产环境使用：

~~~dotenv
SEED_DATA=false
DEMO_SEED=false
~~~

此时不得导入 `demo-seed.sql`，并应通过正式账号管理流程创建账号。安装脚本的健康检查会在 `DEMO_SEED=false` 时跳过演示账号登录检查，但仍会检查 API 和 Web 可达性。

### 6.5 手工初始化（不使用安装脚本时）

以下命令仅用于已安装 PostgreSQL 的隔离数据库。密码通过交互提示或受保护环境变量提供，不要把真实密码写入命令历史：

~~~bash
sudo -u postgres psql -c "CREATE ROLE agri LOGIN PASSWORD '<DATABASE_PASSWORD>';"
sudo -u postgres createdb -O agri agri
sudo -u postgres psql -d agri -c 'GRANT USAGE,CREATE ON SCHEMA public TO agri;'
~~~

启动 API 后等待 Flyway 完成，再导入演示种子：

~~~bash
PGPASSWORD='<DATABASE_PASSWORD>' psql \
  -h 127.0.0.1 -p 5432 -U agri -d agri \
  --set=ON_ERROR_STOP=1 --file=/srv/agriloop/current/db/demo-seed.sql
~~~

验证迁移和种子：

~~~bash
sudo -u postgres psql -d agri -c \
  "SELECT version, description, success FROM flyway_schema_history ORDER BY installed_rank;"
PGPASSWORD='<DATABASE_PASSWORD>' psql -h 127.0.0.1 -U agri -d agri -c \
  "SELECT entity_type, count(*) FROM entity_record GROUP BY entity_type ORDER BY entity_type;"
PGPASSWORD='<DATABASE_PASSWORD>' psql -h 127.0.0.1 -U agri -d agri -c \
  "SELECT username, role_code, enabled FROM user_account ORDER BY username;"
~~~

预期为五条成功迁移记录、三块地块及三个演示账号。种子脚本使用 `ON CONFLICT DO NOTHING`，可重复执行，不删除或覆盖其他业务数据。

## 七、发布包安装

### 7.1 操作目的

把不含源码的发布包安装到统一运行目录，创建 `agriloop` 运行用户、受保护环境文件、数据库账号、Supervisor/Nginx 配置和共享数据目录。

### 7.2 执行命令

在解压出的发布包根目录执行：

~~~bash
cd /opt/agriloop-release/agriloop-release-linux-x86_64
sudo chmod 0755 bin/*.sh
sudo ./bin/install.sh \
  --root /srv/agriloop \
  --env-file /srv/agriloop/shared/.env
~~~

安装脚本的实际顺序为：检查 Ubuntu/x86_64 和权限；安装 Java、PostgreSQL、Redis、Mosquitto、Nginx、Supervisor 等依赖；创建用户和目录；生成或读取 `.env`；创建数据库账号；启动依赖；安装本地 MQTT、日志轮转、定时备份、Nginx 和 Supervisor 配置；切换 `/srv/agriloop/current`；启动 API 触发 Flyway；按 `DEMO_SEED` 导入演示种子；启动 Nginx 并执行健康检查。

### 7.3 预期结果

命令末尾应出现类似以下信息：

~~~text
agriloop health: OK
AgriLoop 0.1.0 installed under /srv/agriloop
~~~

安装完成后目录结构为：

~~~text
/srv/agriloop/
├── current -> releases/0.1.0
├── releases/0.1.0/
└── shared/
    ├── .env                 # 0600，仅 agriloop 可读
    ├── data/
    ├── attachments/
    ├── logs/
    └── backups/
~~~

### 7.4 无 systemd 环境

发布脚本优先使用 systemd；当 PID 1 不是 systemd（例如容器中为 `bash`）时，`bin/service-lib.sh` 使用 `service`、`pg_ctlcluster`、后台守护进程和 Supervisor 自身完成启动。此模式仍要求 root 权限，并在容器内提供可写的 `/run`、`/var/lib` 和 `/var/log`。

### 7.5 Linux Docker 部署方式

当主机不允许安装 Supervisor、Nginx 或 PostgreSQL 系统服务，或者需要将依赖隔离在容器中时，可使用发布包内的 Docker Compose 配置。该方式适用于 Linux x86_64，也适用于安装了 Docker Engine 的其他 Linux 架构（基础镜像和 JAR 必须支持目标架构）。

#### 7.5.1 前置条件

安装 Docker Engine 24 或更高版本及 Docker Compose V2。Docker 官方安装方式见 [docs.docker.com/engine/install](https://docs.docker.com/engine/install/)。确认命令可用：

~~~bash
docker version
docker compose version
~~~

#### 7.5.2 准备发布包和配置

~~~bash
mkdir -p /opt/agriloop-docker
cd /opt/agriloop-docker
unzip /path/to/agriloop-release-linux-x86_64.zip
cd agriloop-release-linux-x86_64
cp config/docker/env.example .env
chmod 600 .env
database_password="$(openssl rand -hex 24)"
jwt_secret="$(openssl rand -hex 32)"
sed -i.bak "s/CHANGE_ME_DATABASE_PASSWORD/$database_password/; s/CHANGE_ME_USE_AT_LEAST_32_RANDOM_BYTES/$jwt_secret/" .env
rm -f .env.bak
unset database_password jwt_secret
docker compose --env-file .env -f config/docker/docker-compose.yml config --quiet
~~~

配置命令无输出且退出码为 0 表示 Compose 文件有效。`WEB_BIND_ADDRESS` 默认为 `127.0.0.1`；需要由外部负载均衡器转发时，将其改为 `0.0.0.0`，并在防火墙中只开放 Web 端口。

#### 7.5.3 启动和验证

~~~bash
docker compose --env-file .env -f config/docker/docker-compose.yml up -d --build
docker compose --env-file .env -f config/docker/docker-compose.yml ps -a
curl --fail --silent --show-error http://127.0.0.1:3000/actuator/health
~~~

预期 `postgres`、`redis`、`mqtt`、`api`、`web` 为 `Up` 或 `healthy`，`seed` 为 `Exited (0)`，健康接口返回 `{"status":"UP"}`。页面入口为 `http://<主机地址>:3000/agriloop/` 等四个路径。数据库迁移和演示种子由 Compose 的 `api` 健康条件及 `seed` 服务按顺序完成。

#### 7.5.4 停止、重启和日志

~~~bash
docker compose --env-file .env -f config/docker/docker-compose.yml logs --tail 100 api web seed
docker compose --env-file .env -f config/docker/docker-compose.yml stop
docker compose --env-file .env -f config/docker/docker-compose.yml start
~~~

`stop` 和 `start` 保留数据库 volume。确认已完成数据备份后才执行 `docker compose ... down -v`，该命令会删除 Compose 管理的数据库和缓存卷。

### 7.6 常见错误

| 错误 | 处理 |
|---|---|
| `install.sh must run as root` | 使用 `sudo` 重新执行 |
| `set DATABASE_PASSWORD` | 检查 `/srv/agriloop/shared/.env`，确保密码不是 `CHANGE_ME` 且不含未转义换行 |
| `unable to start required service` | 查看对应服务状态和系统日志；容器环境确认安装了 `service` 或使用 `--skip-apt` 前先手工安装软件 |
| `extract ... outside releases` | 将 ZIP 解压到 `/opt/agriloop-release` 等临时目录，不要解压到 `/srv/agriloop/releases` |
| Nginx 配置测试失败 | 执行 `sudo nginx -t`，检查 80 端口和 `/srv/agriloop/current` 是否存在；修复后运行 `sudo ./bin/restart.sh --root /srv/agriloop` |

## 九、部署成功验证

### 9.1 本机健康检查

执行目录为任意目录，API 与 Nginx 已启动：

~~~bash
curl --fail --silent --show-error http://127.0.0.1/actuator/health
~~~

预期返回 JSON，包含：

~~~json
{"status":"UP"}
~~~

### 9.2 三角色登录和授权范围

登录接口返回的 `data.accessToken` 是 JWT（JSON Web Token，一种带签名的无状态会话令牌）。以下示例不打印令牌到日志：

~~~bash
BASE_URL=http://127.0.0.1
LOGIN_JSON="$(curl --fail --silent --show-error -X POST "$BASE_URL/api/v1/auth/login" \
  -H 'Content-Type: application/json' \
  -d '{"username":"admin","password":"demo123"}')"
TOKEN="$(printf '%s' "$LOGIN_JSON" | python3 -c 'import json,sys; print(json.load(sys.stdin)["data"]["accessToken"])')"
curl --fail --silent --show-error "$BASE_URL/api/v1/auth/me" \
  -H "Authorization: Bearer $TOKEN"
~~~

分别替换用户名为 `farmer`、`admin`、`sysadmin`，初始密码均为 `demo123`。预期角色和范围如下：

| 用户名 | 预期 `role` | 预期范围 |
|---|---|---|
| `farmer` | `FARMER` | `plot-a01`、`plot-a02` |
| `admin` | `FARM_ADMIN` | `farm-demo` 的全部三块地 |
| `sysadmin` | `SYSTEM_ADMIN` | 平台级 |

### 9.3 模拟遥测

使用 `admin` 令牌执行：

~~~bash
curl --fail --silent --show-error "$BASE_URL/api/v1/plots/plot-a01/telemetry?limit=20" \
  -H "Authorization: Bearer $TOKEN"
~~~

预期返回 `data` 数组，包含 `SOIL_MOISTURE`、`AIR_TEMPERATURE`、`LIGHT` 等模拟指标；事件中的 `sourceMode` 应为 `SIMULATION`，`provenance` 为 `OBSERVED`，不能标记为真实硬件。

### 9.4 SSE 事件流

SSE 连接需要 JWT。用短超时观察心跳或模拟器事件：

~~~bash
timeout 20 curl --no-buffer --silent --show-error \
  "$BASE_URL/api/v1/events/stream" \
  -H "Accept: text/event-stream" \
  -H "Authorization: Bearer $TOKEN"
~~~

预期连接保持打开并收到 `event:`/`data:` 行或心跳；`timeout` 主动结束连接属于正常现象。若立即返回 401，检查令牌；若无事件，检查 `SIMULATOR_AUTO_START=true` 和 `api.log`。

### 9.5 虚拟灌溉闭环

先取得处方：

~~~bash
PLAN_JSON="$(curl --fail --silent --show-error -X POST "$BASE_URL/api/v1/irrigation/estimate" \
  -H 'Content-Type: application/json' -H "Authorization: Bearer $TOKEN" \
  -d '{"plotId":"plot-a01","scenarioId":"normal"}')"
printf '%s\n' "$PLAN_JSON"
~~~

在返回的 `data.planId` 和 `data.waterLitre` 基础上，使用明确确认和新的幂等键执行。若当前读数处于安全门允许范围，可执行：

~~~bash
curl --fail --silent --show-error -X POST "$BASE_URL/api/v1/commands/virtual" \
  -H 'Content-Type: application/json' -H "Authorization: Bearer $TOKEN" \
  -d '{"plotId":"plot-a01","planId":"<PLAN_ID>","confirmed":true,"idempotencyKey":"acceptance-irrigation-001"}'
~~~

预期返回 `data.status=CONFIRMED` 或 `APPROVED`、`data.type=IRRIGATION_START`，并带有 `commandId`。等待约 2 秒后查询：

~~~bash
curl --fail --silent --show-error "$BASE_URL/api/v1/commands/<COMMAND_ID>" \
  -H "Authorization: Bearer $TOKEN"
curl --fail --silent --show-error "$BASE_URL/api/v1/commands/<COMMAND_ID>/evaluation" \
  -H "Authorization: Bearer $TOKEN"
~~~

在 `COMMAND_MODE=virtual` 且处方通过安全门时，ACK 应为 `SUCCEEDED`，效果评价应记录实际用水、土壤湿度变化和水资源余额扣减。若设备离线、数据质量不足或处方为夜间/无需操作，系统应返回明确的 `NEEDS_EVIDENCE`、`UNAVAILABLE` 或 `NO_ACTION`，不能强行标记成功；验收时应重新获取新处方，不重复使用过期幂等键。

### 9.6 页面入口

在浏览器访问：

~~~text
http://<服务器地址>/agriloop/
http://<服务器地址>/farm-admin/
http://<服务器地址>/farmer/
http://<服务器地址>/system-admin/
~~~

公网实例对应本章 1.2 的 HTTPS 地址。页面首屏应能加载，登录后角色路由和地块范围应与 `/api/v1/auth/me` 一致；系统管理员页面在无模型服务时应显示规则模式或降级状态。

安装脚本使用版本目录和 `current` 符号链接，保留 `shared` 数据；失败时会尝试恢复上一个 `current`。升级后必须重新执行第九章验证，不要把旧发布目录中的源码、日志或 `.env` 复制进新包。

| Nginx 访问日志 | `/srv/agriloop/shared/logs/nginx-access.log` |
| Nginx 错误日志 | `/srv/agriloop/shared/logs/nginx-error.log` |
| Supervisor 启动日志 | `/srv/agriloop/shared/logs/supervisord.log` |
| Mosquitto（无 systemd 回退） | `/var/log/agriloop-mosquitto.log` |

日志轮转配置安装到 `/etc/logrotate.d/agriloop`，默认每日轮转、保留 7 份并压缩。排查问题时使用 `tail` 或 `supervisorctl`，不要把日志归档到发布包。

### 11.2 备份

定时任务安装到 `/etc/cron.d/agriloop-backup`，每天 03:17 使用 `pg_dump` 写入：

~~~text
/srv/agriloop/shared/backups/agri-YYYYMMDD-HHMMSS.sql.gz
~~~

手工执行：

~~~bash
sudo /srv/agriloop/current/bin/backup.sh --root /srv/agriloop
ls -lh /srv/agriloop/shared/backups
~~~

备份文件包含运行数据库，属于敏感材料，必须使用受限权限和离线存储；不要放入源码包或发布 ZIP。

### 11.3 恢复原则

恢复前停止 API，创建新的临时数据库验证备份，不要直接覆盖正在运行的生产库：

~~~bash
sudo -u postgres createdb -O agri agri_restore_check
gzip -dc /srv/agriloop/shared/backups/agri-<timestamp>.sql.gz \
  | PGPASSWORD='<DATABASE_PASSWORD>' psql -h 127.0.0.1 -U agri -d agri_restore_check \
      --set=ON_ERROR_STOP=1
PGPASSWORD='<DATABASE_PASSWORD>' psql -h 127.0.0.1 -U agri -d agri_restore_check \
  -c 'SELECT count(*) FROM entity_record;'
~~~

确认数据和版本后，按组织的变更审批流程切换数据库连接并执行第八、九章验证。演示种子不能用于恢复生产数据。

## 十二、常见问题处理

| 现象 | 诊断命令 | 处理方法 |
|---|---|---|
| API 不健康 | `tail -n 100 /srv/agriloop/shared/logs/api-error.log` | 核对 Java 17、数据库 URL/密码和 Flyway 日志；修复后 `restart.sh` |
| 数据库连接失败 | `pg_isready -h 127.0.0.1` | 启动 PostgreSQL，核对 `.env` 的四项数据库参数和账号权限 |
| Flyway 迁移失败 | `psql -d agri -c 'SELECT * FROM flyway_schema_history;'` | 先修复失败版本；不要手工修改版本表或跳过迁移 |
| Redis 健康降级 | `redis-cli ping` | 启动 Redis；规则和数据库功能仍可运行，但 Streams 实时链路需要 Redis |
| MQTT 不可用 | `ss -lntp | grep 1883` | 检查 Mosquitto 配置和 `/var/log/agriloop-mosquitto.log`；仿真命令会显示内存回退，不得宣称真实设备执行 |
| Nginx 502 | `curl http://127.0.0.1:8080/actuator/health` | 先恢复 API，再 `nginx -t && nginx -s reload` |
| 页面 404 或资源白屏 | `ls /srv/agriloop/current/web/index.html` | 确认 `current` 指向完整版本目录和 Nginx root；不要把源码目录设为 root |
| 端口 80 冲突 | `ss -lntp | grep ':80'` | 停止无关 Web 服务或调整外部端口映射；不改变 API 本机监听约束 |
| 三账号登录失败 | `SELECT username,role_code FROM user_account;` | 仅在隔离验收库确认 `DEMO_SEED=true` 后重新运行种子；生产环境使用正式账号流程 |
| 灌溉显示 `NEEDS_EVIDENCE` | 查询 `/plots/{plotId}/telemetry` 和 `/irrigation/estimate` | 等待模拟器生成新鲜 `GOOD` 数据，确认设备在线和地块授权；不要绕过安全门 |
| AI 显示降级 | `grep AI_MODE /srv/agriloop/shared/.env` | 这是模型未启动时的预期行为；启动兼容 vLLM 后再改为 `openai-compatible` 并重启 API |
| Windows Gradle 测试类找不到 | 在中文路径执行 Gradle | 将仓库映射到 ASCII 路径或在 Linux 执行；详见开发文档 13.4 |

## 十三、安全要求

1. `/srv/agriloop/shared/.env` 权限必须为 `0600`，仅 `agriloop` 和 root 可读；不得提交 Git、上传 ZIP 或写入文档。
2. `JWT_SECRET` 至少 32 个随机字节；数据库密码和系统管理员授权码使用独立随机值，禁止使用示例值。
3. 防火墙只开放 Nginx 对外端口（通常为 80/443 或云平台映射端口）。PostgreSQL、Redis、MQTT、API 和 vLLM 只监听回环地址。
4. 演示账号 `demo123` 仅用于初次安装检查，部署完成后立即通过改密接口更换；操作记录不得泄露令牌、恢复码或个人信息。
5. `COMMAND_MODE=virtual` 只表示软件仿真。启用真实硬件前必须单独完成设备绑定、权限、审批、幂等、ACK 超时和现场安全评估。
6. 备份、附件和日志目录必须使用访问控制和容量监控；不同安装环境之间不得复制数据库、配置、日志、备份或模型文件。

## 十四、功能范围与使用限制

### 14.1 支持范围

部署范围包括：Ubuntu 22.04 x86_64 原生部署或 Docker 部署，Windows 10/11 与 macOS 12 或更高版本 Docker Desktop 部署；Java 17；PostgreSQL、Redis、Mosquitto、Supervisor、Nginx；五个 Flyway 迁移；虚拟演示种子；三角色 JWT 登录和范围校验；进程内模拟遥测；REST 查询；SSE 事件流；规则模式下的诊断、处方、虚拟灌溉、ACK 和效果记录；停止、重启、状态和健康检查脚本。

BearPi HM Nano + E53_IA1 支持真实遥测以及板载风扇/补光灯链路。真实水泵、阀门、其他传感器、其他 GPIO 执行器、鸿蒙端和生产级视觉/语音能力需要增加相应适配器、设备合同和部署配置。

### 14.2 独立环境安装检查

首次安装或功能演示时，建议使用独立主机或 Docker volume，并采用以下配置；不需要本地大模型即可完成安装检查：

~~~dotenv
SPRING_PROFILES_ACTIVE=simulation
APP_MODE=simulation
AI_MODE=rules-only
COMMAND_MODE=virtual
~~~

安装检查只导入 `demo-seed.sql` 和运行过程中生成的模拟数据，不复制其他环境的数据库、`.env`、日志、备份或模型文件。检查记录应包含命令输出、健康响应、三角色 `/auth/me` 响应、模拟遥测、SSE、虚拟灌溉 ACK/效果和服务控制结果。
