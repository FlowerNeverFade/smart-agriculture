# 巡田记录与补证申请双角色可见验收记录

> 功能编号：T-135

> 当前范围：本地代码、测试与服务器发布；`main@165aefd9` 已同步 `/srv/agriloop`，健康检查和公网静态入口通过，登录后的双角色浏览器验收待集中执行。

## 1. 验收目标

- 农户提交巡田记录后，记录立即出现在自己的巡田记录中，刷新后仍可读取。
- 农户只能读取本人提交或关联任务分配给本人的巡田记录；补证申请只能读取本人创建或分配给本人的记录。
- `FARM_ADMIN` 在授权当前农场内可读取全部巡田记录和补证申请，跨农场请求返回 `403`。
- 巡田记录和 `sourceType=READINESS` 的补证申请必须先成功写入数据库，再返回成功并发布 SSE；数据库不可用返回 `503 OPERATION_RECORD_PERSISTENCE_UNAVAILABLE`。
- 读取失败保留已有数据并显示错误/重试入口，不能把失败伪装成空列表；照片上传失败与核心巡田记录保存分开提示。

## 2. 实现证据

| 范围 | 结果 |
| --- | --- |
| API 读取 | `GET /api/v1/inspections` 支持 `farmId`、`plotId`，保留 `GET /api/v1/plots/{plotId}/inspections` 兼容入口；服务端按农场、地块和角色过滤。 |
| 巡田持久化 | `AgriStore.saveDurably` 先写数据库，成功后更新读模型；失败不发布成功事件。 |
| 补证持久化 | 保存 `evidenceType`、`requesterId/requesterName`、`farmId`、`plotId`、`reason`、`createdAt`、`status`，类型限定为 `FIELD_INSPECTION`、`RETEST`、`DEVICE_CHECK`。 |
| SSE | `inspection.created` 只发送给相关农户；补证工单事件按创建人/分配人裁剪，管理员刷新现有农务任务内的对应分区。 |
| 农户端 | 提交成功先插入服务端返回记录，再执行一次正式刷新；保留失败数据，错误状态提供重试按钮。 |
| 管理员端 | 复用“农务任务”页面，增加独立补证申请区；`OPEN` 申请可进入现有分配流程；巡田记录默认最新 8 条，可展开全部。 |

## 4. 浏览器验收

本轮在代码、自动化测试和生产构建完成后集中执行了一次本地浏览器验收。已检查：农户演示提交巡田记录后立即显示、刷新后仍可见；管理员进入现有“农务任务”页后可看到巡田记录区、提交人/地块/现场说明/照片/关联任务字段，以及独立于“进行中”筛选的补证申请区。切换演示身份时本地浏览器 URL 安全策略中断，未把管理员看到最终 `OPEN` 补证申请、移动端最终布局和控制台最终状态写成已通过，也未使用其他浏览器或绕过策略重试。在线地址当前会跳转到登录页，本轮不录入账号、不直接操作线上数据；推送后仍需部署服务器，再做一次线上验收。

## 5. 失败与降级口径

- 数据库写入失败：接口返回 `503`，前端提示未保存，不显示“提交成功”。
- 巡田核心记录已保存但照片上传失败：明确提示“巡田记录已保存，照片上传失败”。
- 读取失败：保留上一次成功读取的数据，显示错误和“重试读取”，不显示“暂无记录”。
- 在线服务器未部署本提交前，公网页面的旧行为不作为本轮验收证据。
