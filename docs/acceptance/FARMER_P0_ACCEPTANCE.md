### 1.1 本轮安全门简化与补证闭环

- readiness 合同统一返回 `blockingEvidence`、`advisoryEvidence` 和 `executionAllowed`；`missingEvidence`、`conflicts` 继续作为兼容及审计字段，前端不再用 `missingEvidence` 直接禁用执行。
- 仅在新鲜且 `GOOD` 的土壤湿度、设备在线、无高置信漂移/故障、非暴雨、资源/权限/时长通过、湿度不低于 Crop Pack 自动浇水阈值且模式为 `OPERATOR_CONFIRMED` 时，把 `MORE_DIAGNOSIS_EVIDENCE` 和 `HUMAN_EVIDENCE_REVIEW` 放入提醒；自动浇水和应急路径不适用此降级。
- 普通巡田没有便携仪值时只保存现场观察；`RETEST` 必须填写便携仪值。匹配复测将旧冲突标记为 `RESOLVED`，不匹配复测将旧冲突标记为 `SUPERSEDED`，不会删除历史证据。
- 线上/正式 API 与演示 API 使用同一字段和行为；本期只验证模拟数据、数据库记录和虚拟执行，不涉及真实硬件或线上发布。

### 1.2 消息中心未读状态与打开即读

- 消息列表只对 `read=false` 的单条消息渲染红色未读点，未读数量、消息分类和顶部“一键清除已读”保持不变。
- 点击列表消息或首页最近动态中的消息入口后，立即仅将当前消息改为已读；进入消息中心列表不会批量清除其他未读消息，重复打开已读消息幂等且不弹提示。
- 已读 ID 使用 `agriloop_read_messages:<mode>:<encodedAccountId>` 保存在浏览器；账号优先使用 `userId`、回退用户名，正式和演示模式相互隔离。缺失、损坏或不可写时按空集合/内存状态继续展示，不阻塞消息中心。
- 页面刷新会恢复本账号本模式的已读状态；该状态不跨浏览器或设备同步，也不写入告警、任务、巡田记录或后端 API。
- 详情页不再提供“标记已读/已读”按钮，分析和现有消息跳转操作保持不变。

### 1.3 灌溉入口、水量校验与布局修复

- 输入：当前选中地块的灌溉处方、地块所属农场的水量档案/当日余额、操作权限、单次与最大时长限制，以及演示模式的虚拟余额。
- 处理：人工浇灌入口不再由 `manualFallback.available` 控制显示；有处方即可打开，打开和提交时重新校验处方上下文、权限、单次/每日水量、资源余额、最大时长和幂等键。正式 readiness、处方、命令统一通过 `plotId -> farmId -> resource-profile` 读取水量；终态历史成功命令不重复计入当前容量，演示成功/部分成功同步更新顶部余额。
- 输出：正常和 `NO_ACTION` 地块均可见“人工浇灌”入口；资源充足时弹窗显示当前余额并可继续确认，资源、权限或时长确实不足时返回明确错误；灌溉建议区域为单列布局，保留卡内紧凑湿度趋势，避免重复大图造成左侧空白。
- 失败/降级：处方尚未加载时只提示稍候；缺少权限、资源余额、单次/每日水量、时长或幂等条件时不执行；异常/漂移/坏数据/过期/离线/暴雨等既有硬门不因按钮可见而删除。所有执行仍为 `SIMULATED`，不连接真实硬件。
- 验收证据：Web Node 34/34、定向 Java 3/3、后端 `compileJava/compileTestJava`、JavaScript 语法检查、Vite 62 modules、`git diff --check` 和本地桌面/390px 浏览器检查通过；本轮未推送或部署线上。

### 1.4 农户导航滚动状态隔离

- 输入：当前农户路由、导航目标和 `.farmer-main` 当前滚动位置。
- 处理：`navigate` 先完成页面状态与 hash 更新，再仅在逻辑页面发生变化时将 `#farmer_app .farmer-main.scrollTop` 设为 `0`；同一页面重复点击不重置位置。
- 输出：从主面板或其他农户页面切换到新页面时，新页面从顶部开始，URL hash 和原有路由状态保持不变。
- 失败/降级：主内容容器尚未挂载或页面正在初始化时安全跳过滚动操作，不阻断导航，也不改变业务数据、权限或接口行为。
- 验收证据：农户定向 Node 14/14、`node --check js/farmer.js`、Vite 62 modules、`git diff --check` 通过；本地 415px 窄屏将主面板滚到底部后切换“我的地块”，滚动值回到 `0`，页面标题切换正确，控制台错误为 `0`。

## 2. API 与安全证据

- `GET /api/v1/decisions/{subjectType}/{subjectId}/readiness`：返回 `blockingEvidence`、`advisoryEvidence`、`executionAllowed`、兼容 `missingEvidence`/`conflicts` 和 `policyVersion=readiness-v2`。
- `GET /api/v1/plots/{plotId}/irrigation-guard`：统一返回迟滞、无时间冷却的灌溉可用状态和自动浇水阈值。
- `POST /api/v1/irrigation/auto`：对低于 10% 的合格土壤遥测发起虚拟浇水；同一事件只按幂等键处理一次。
- `GET /api/v1/irrigation/plans/{planId}`：按地块权限读取原处方。
- `POST /api/v1/decisions/{traceId}/feedback`：旧审批申请合同继续校验 trace/plan/plot 和幂等键；当前灌溉建议改用 `POST /api/v1/commands/virtual`，携带 `confirmed=true` 和幂等键。
- `POST /api/v1/commands/virtual`：农户和管理员均可在授权地块对 READY 处方直接创建虚拟灌溉命令；不创建管理员审批工单。
- 灌溉 readiness、处方和命令均按地块所属农场读取水量档案；资源限制以当日余额、单次上限和最大时长为准，已完成历史命令不重复占用容量。本轮未修改 OpenAPI 合同。
- `POST /api/v1/scenarios/compare`：校验地块权限，返回冻结快照和双轨分支，不写回遥测。
- 命令、评价和决策护照按地块鉴权；跨地块读取返回拒绝。
- 灌溉命令不从 ACK 推导时间冷却；`FAILED/TIMEOUT` 仍不会改变土壤湿度，告警静默期与执行保护分开计算。

## 6. 失败与降级边界

- 指标未声明或没有遥测时显示 `UNAVAILABLE`，不生成目标范围或曲线。
- 数据漂移、设备故障、坏/过期数据、设备离线、暴雨、资源/权限/时长限制或自动/应急安全门不足时阻断可执行处方；只有满足低风险人工确认条件时，证据不足/人工冲突才降为黄色提醒，证据本身仍保留。
- 顶部水库余额与地块人工浇灌限制使用同一地块所属农场水量档案；余额充足不绕过权限、单次/每日水量、最大时长或幂等校验，确实不足时仍返回资源错误。
- 补证申请创建后不宣称安全门已解除；匹配复测才会把旧冲突标记为 `RESOLVED`，新冲突则只让最新记录保持有效。普通巡田没有便携仪值时不伪造复测。
- 重复直接执行、旧审批和补证请求均复用幂等结果；直接执行不重复创建命令或审批工单。
