# 基于合格经验的受控学习

## 目标与边界

受控学习把反馈、告警闭环和效果评价形成的案例统一整理为可审计的学习记录。模型只能参与自动初筛和相似案例排序，最终是否进入正向经验由确定性质量门决定。系统不会在线修改模型权重、生产阈值、规则或设备控制逻辑；训练集导出也是离线、人工批准后的独立步骤。

## 数据流

```text
告警/决策 + 遥测快照 + 诊断证据 + 命令 ACK + 效果评价 + 反馈
        -> decision-case / alert-learning-case
        -> 规范化并冻结 sourceSnapshot
        -> ControlledLearningService 确定性质量评估
        -> PENDING / QUALIFIED / REJECTED
        -> 正向检索、策略候选或反例回归（按 learningUses 隔离）
```

案例保存于现有 `entity_record` 存储，不新建平行事实表。两个历史案例流以 `caseId` 去重，并保留 `caseType` 以便审计。创建和重复重评估均使用案例指纹与评估器版本，重复请求不会生成新的案例或重复闭环记录。

## 质量状态与质量门

- `PENDING`：记录已存在，但缺少完成判断所需的信息，例如效果评价、执行结果或可复现标记。
- `QUALIFIED`：输入快照完整、证据可追溯、规则/安全/资源/权限检查通过，执行有成功或可评价的部分 ACK，效果评价完成，并且案例可复现或已人工审核。
- `REJECTED`：硬性排除条件命中，包括遥测过期/缺失/坏质量、漂移或冲突、无 ACK、失败/超时、不可评价效果、规则或安全门失败、模型猜测、未确认的模拟结果。记录不删除，只进入反例和审计范围。

质量分数为后台筛选用的 0--100 分值，不向普通用户展示为模型置信度：数据与新鲜度 20 分、诊断证据 20 分、执行结果 25 分、效果评价 20 分、反馈与可复现性 15 分。每次判定同时记录 `selectionReason`、`excludedReason`、`pendingReason`、`qualityDecision` 和 `qualityEvaluatorVersion`。

案例会补齐 `conversationId`、`accountId`、`farmId`、`plotId`、`cropPackVersion`、`scenarioId`、`ruleVersion`、`agentVersion` 和冻结的 `sourceSnapshot`。快照只使用当时的遥测、来源、质量、观测时间及嵌套证据，后续实时读数不会把旧案例“补成合格”。

## 用途隔离

`learningUses` 只允许以下值：

- `POSITIVE_RETRIEVAL`：仅 `QUALIFIED` 案例可用于相似案例检索；
- `STRATEGY_CANDIDATE`：合格案例达到最小数量后才可形成候选；
- `OFFLINE_TRAINING`：仅人工审核确认的合格案例可导出；
- `NEGATIVE_EVALUATION`：`REJECTED` 案例只能作为反例、拒答和回归测试；
- `NONE`：不参与学习。

检索按当前角色、账号、农场、地块和会话过滤。明确地块时只返回同一地块；没有地块时只返回同样没有地块的农场级案例，不会因为缺少参数而扩大到其他地块。跨农场复用必须由系统管理员带批准标记，并仍保留会话和账号隔离。

## 策略候选状态机

```text
DRAFT -> OFFLINE_VALIDATED -> APPROVED -> ACTIVE -> ROLLED_BACK
  |              |               |
  +------------> REJECTED <------+ 
```

候选生成只引用 `QUALIFIED` 案例，并记录引用案例列表、基线策略和候选策略。离线验证使用固定 `seed`、冻结案例摘要和 `replayHash`，检查成功率、安全门、资源约束和质量门回归；失败不能推进状态。`OFFLINE_VALIDATED` 不能直接启用，必须由有权限的管理员单独批准。启用前会再次确认引用案例仍为合格；激活同签名的新版本会将旧版本标记为 `SUPERSEDED`，`ACTIVE` 候选支持人工回滚。生产策略不会因一次成功执行或一条反馈自动改变。

## 接口与权限

兼容保留 `/api/v1/alert-learning-cases`，同时提供 `/api/v1/learning/cases` 别名。治理接口包括：案例查询和筛选、重新评估、人工纳入/排除、策略候选生成、离线验证、候选状态转换、批准训练集导出和学习审计。

- 系统管理员：跨农场只读、治理、审计和批准离线训练导出；跨农场复用必须显式批准。
- 农场管理员：仅授权农场内的案例和候选，可执行本农场治理操作。
- 农户：仅本人授权地块、任务和反馈相关案例，不可审核或管理策略。

所有服务端查询都会重新根据令牌权限校验 `farmId`、`plotId`、账号和会话，不能通过修改请求参数越权。

## 失败与降级

案例库、质量评估或离线验证不可用时，普通 AI 仍可使用已有规则和普通检索；前端应显示规则/检索降级，不伪装成已经完成学习。学习服务异常不会阻塞普通查询或既有安全控制，也不会生成未经验证的灌溉和设备命令。模型权重更新、阈值调整和规则发布均不在本闭环内，必须由独立、可审计、可回滚的离线流程完成。

## 版本与回滚

每条案例保存规则、Crop Pack、Agent 和评估器版本；每次离线回放保存场景、随机种子、证据案例结果和哈希。候选批准、启用、替换和回滚分别记录操作人、时间、修订号和审计事件。回滚只恢复上一已批准策略，不删除案例，也不会修改模型权重。

## 验收口径

应至少验证：完整成功闭环可成为 `QUALIFIED`；失败、超时、漂移、冲突、过期和无 ACK 案例不会进入正向检索；排除案例仍可查到并标记 `NEGATIVE_EVALUATION`；候选不能跳过离线验证和人工批准；重复评估幂等；会话/地块/角色范围不泄漏；AI 降级不阻塞安全控制。完整测试套件和线上部署不属于本次本地实现交付。
